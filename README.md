# 🔥 모닥모닥 (MODAK MODAK) — Backend

> 계획을 실행으로 바꾸기 위한 **모각공 메이트 매칭 웹**
> ECC Winter Project · Team 3

함께 공부할 사람을 찾고 일정을 맞추는 번거로움을 줄이기 위해 만든 서비스입니다. 비동기로 모각공 **팟**을 열고, 참여 신청을 받아 팟장이 승인하면 모임이 확정됩니다.
만남이 한 번으로 끝나지 않도록 **목표 설정 → 참여·출석 → 회고 → 메이트** 흐름으로 학습 과정을 기록합니다.

- 🎨 Frontend: [modakmodak-FE](https://github.com/ECC-modakmodak/modakmodak-FE)
- 📄 API 문서(배포 서버): [Swagger UI](https://modakmodak-be.onrender.com/swagger-ui/index.html)

<br>

## 🧩 문제 정의

| 문제 | 해결 방향 |
| --- | --- |
| 모각공 메이트를 찾고 일정을 조율하는 과정이 번거로움 | 팟 생성 → 참여 신청 → 팟장 승인으로 비동기 매칭 |
| 만남 중심 스터디는 일회성으로 끝나기 쉬움 | 팟 목표 설정, 출석 기록, 회고로 학습 과정을 기록 |
| 노쇼로 모임이 깨짐 | 출석·참여율 기록을 프로필에 노출 |

<br>

## 💡 설계 포인트

- **3-Layer 구조**: Controller–Service–Repository로 역할을 나누고, 알림과 팟 로직은 별도 서비스로 분리해 결합도를 낮춤
- **트랜잭션으로 정합성 보장**: `신청 승인 + 인원 갱신`을 하나의 트랜잭션으로 묶고 실패하면 롤백
- **정원 초과 방지**: 승인 직전에 현재 인원과 정원을 다시 비교해 초과 승인을 차단
- **권한 검증**: 서버에서 요청 유저 ID를 대조해 팟장 권한 위조를 막음
- **도메인 모델링**: 팟 유형·분위기·상태는 Enum으로 규격화, 메이트는 Self-Referential 연관관계로 구현
- **입력 검증**: 아이디 4~20자(영문·숫자, 중복 확인), 비밀번호 8~20자(영문 + 숫자 + 특수문자 조합)

## 🔥 트러블슈팅

### 팟 정원 초과 승인
- **문제**: 참여 승인과 인원 갱신이 따로 처리되면, 신청이 몰릴 때 정원보다 많이 승인되거나 인원 수가 어긋날 수 있었음
- **해결**: 두 작업을 하나의 트랜잭션으로 묶고, 승인 직전에 현재 인원과 정원을 다시 비교

<br>

## 🚀 실행 방법

```bash
git clone https://github.com/ECC-modakmodak/modakmodak-BE.git
cd modakmodak-BE
cp .env.example .env   # DB, Google OAuth 값 입력
./gradlew bootRun
```
API 문서: `http://localhost:8080/swagger-ui/index.html`
